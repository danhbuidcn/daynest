Hệ thống chạy thế nào, qua sơ đồ và 5 luồng chính. Theo code v5.0.1 (hết S5), cập nhật 2026-10-14. Gặp chỗ lệch với code → tin code.

1.Daynest là gì

App cá nhân trên điện thoại, 3 phần: Lịch (dương + âm, ngày lễ, event, todo, chu kỳ kinh nguyệt), Ghi chú, Chi tiêu. Android + iOS, viết bằng Expo (React Native + TypeScript).

2.Quyết định lớn nhất: không có backend tự viết

  • Không có server Go/Node. PostgREST tự sinh REST API từ bảng. App gọi thẳng supabase.from('events').select().
  • Quyền truy cập do Postgres quyết định. Mọi bảng có RLS (Row Level Security, luật lọc dòng ngay trong DB): user_id = auth.uid() AND session_active(). App không tự kiểm tra quyền.
  • Logic nghiệp vụ nằm trong app: trải event lặp, âm lịch, đặt nhắc, đồng bộ Google đều chạy trên máy.

Lý do: app cá nhân, gói Supabase Free, không muốn vận hành server. Đổi lại, app phải tự lo nhiều việc.

4.Flow 1: mở app và đăng nhập

Code: app/src/app/_layout.tsx, app/src/features/auth/AuthProvider.tsx

  • Đăng nhập: Google Sign-In SDK → idToken → supabase.auth.signInWithIdToken → phiên Supabase (JWT) → rpc('register_device').
  • Giới hạn 2 thiết bị: bảng user_devices. Máy thứ 3 đăng nhập → register_device đá máy sớm nhất. Máy bị đá biết khi:
    • app quay lại foreground → gọi session_active();
    • 1 lệnh ghi bị RLS từ chối (42501) → ForbiddenError → useForbiddenGuard kiểm tra lại phiên.
  • Server không đẩy thông báo xuống máy, nên app phải tự hỏi.

5.Flow 2: đọc lịch (phần khó nhất)

Code: features/events/useEvents.ts, features/events/api.ts, lib/recurrence/

DB lưu quy tắc, app trải ra từng lần. Event "hằng tháng âm lịch" chỉ là 1 dòng events + vài dòng event_exceptions (bỏ 1 lần / sửa 1 lần).

  • Đang tải khoảng mới → tạm hiện khoảng rộng hơn đã tải, hoặc dữ liệu cũ. Lưới không nháy rỗng.
  • Nới ±1 ngày vì span_start/span_end của event có giờ lưu theo ngày UTC.

6.Flow 3: ghi dữ liệu (không trùng, không mất)

  • Không trùng (idempotency): id sinh lúc mở form, nên mạng chập chờn, gửi lại, bấm 2 lần vẫn chỉ 1 dòng.
  • Khoá lạc quan: 0 dòng được sửa nghĩa là máy khác đã sửa trước → hộp "Đã thay đổi ở thiết bị khác".
  • Lỗi 42501 có ở cả tạo mới và sửa: máy có thể đã bị đá ra.

2 bẫy cần nhớ:
• Giữ updated_at nguyên chuỗi API trả về. Đổi qua Date mất micro giây → so sánh sai → báo xung đột giả.
• Supabase client gửi Cache-Control: no-cache: lớp HTTP của Android từng trả dữ liệu cũ (lib/supabase.ts).

7.Flow 4: đồng bộ Google Calendar 2 chiều

Code: features/google/: sync.ts điều phối, push.ts, pull.ts, lib/google/mapping.ts đổi định dạng

  • id trên Google = id Daynest bỏ dấu -. Hai máy cùng đồng bộ vẫn không tạo trùng.
  • Google trả cancelled → xoá. Kiểu lặp Daynest không biểu diễn được → lưu từng lần thành event chỉ xem (google_readonly).
  • Token Google chỉ ở trên máy, không lưu DB. Bảng google_sync_state giữ sync_token.
  • Tắt đồng bộ → không xoá gì 2 bên; giữ google_event_id để bật lại ghép đúng.

8.Flow 5: nhắc nhở

Code: features/reminders/reminderSync.ts, lib/notifications/pickReminders.ts

Không có server gửi push. Mọi thông báo là thông báo đặt sẵn trên máy.

  • Nguồn: event + todo + chu kỳ sắp tới. Mỗi (lần xảy ra × mốc nhắc) là 1 thông báo.
  • Chạy lần lượt, không chồng nhau. Giới hạn 64 vì iOS chỉ giữ chừng đó thông báo chờ.

10.Tuần đầu

  1. Chạy app: điền app/.env (xin secrets từ người phụ trách; không commit, không dán vào chat) → cd app && npm install && npm run android.
  2. Đọc theo thứ tự: specs/index.md → specs/architecture/index.md → _layout.tsx → AuthProvider.tsx → useEvents.ts.
  3. Chạy test: npm run typecheck && npm run lint && npm test. Đọc lunar.test.ts, recurrence.test.ts để hiểu phần lõi nhanh nhất.
  4. Đổi DB: chỉ qua supabase/db new <tên> → viết SQL + RLS → supabase/db test (cần Docker).
  5. Quy tắc code: theme token @/theme, chữ qua AppText, mọi chuỗi qua i18n (cùng key ở en.json + vi.json). Mỗi việc 1 file trong wip/, duyệt xong mới làm.

Tài liệu kiến trúc đã cũ. specs/architecture/ ghi "theo code tới S2 bước 6": còn đánh dấu "(chưa code)" cho Google sync và nhắc nhở (code đã có), ghi "chưa dùng Edge Functions" (đã có send-bug-report), chưa có todo, chu kỳ, chi tiêu, báo lỗi.
